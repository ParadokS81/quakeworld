## Method (the lift)

`c3-liveness-diff.sh` lifts the proven dump-parser from `diff-runtime.sh`
(header/footer gating, the `%c %s %s` SERVERINFO 1-char-flag-column decode,
CRLF strip, lowercase, `LC_ALL=C` sort) and changes exactly three things,
each with a `# WHY:` in the script:

- (a) DB side is Postgres at the freshly re-extracted commit; source-backing
  is the per-type `*_versions.source_file IS NOT NULL` join (NOT sqlite3 /
  `source_state` -- the transition log is hardcoded branch literals, not a
  reliable source-backing signal).
- (b) Scope is union(ktx,mvdsv) x (cvar,command) -- four per-(engine,type)
  sections (not mvdsv-only like the original tool).
- (c) Discount is the KTX level-shot index cvar family ONLY (the `^k_ls`
  underscore-prefixed bookkeeping family, 181 runtime entries; sole L1 row
  verified count=1, KTX-internal, not an admin knob) -- NOT
  `ktx-progs-prefixes.txt` / `ktx-progs-allowlist.txt`, which match broad
  `k_*` / `qwm_*` prefixes and would wrongly strip legitimate KTX `k_*`
  cvars in the describe-fill scope.

Both sides are CRLF-normalized, case-folded, and `LC_ALL=C` sorted; the
diff is deterministic (re-running yields byte-identical output). Suspects =
**L1-present (source-backed) AND dump-absent**.

Two faithful adaptations were required and are flagged (NOT silent
overrides) -- see the executor report and the script `# WHY:` comments:
the timestamp-prefix strip was generalized to handle the self-built dump's
distinct console-log timestamp shape (a hard-coded field index would
extract a timestamp fragment as the name on the new dump), and the
index-family discount is applied symmetrically to both sides (a one-sided
strip leaves the single source-backed base row as a spurious suspect,
contradicting the contract's stated intent that the family never appears
as a suspect; verified to hide zero other genuine suspects).

### ktx / command -- NON-DIAGNOSTIC (excluded from the suspect pool)

- Set difference: L1 source-backed 358, `cmdlist`-intersection 1, raw
  difference 357. **This is NOT a suspect pool. It is a measurement-invalid
  leg and produces ZERO C3 suspects.**
- **Why the oracle is structurally blind here.** KTX commands are the
  `cmd_t cmds[]` / frogbot `std_commands[]` / `editor_commands[]`
  struct-literal tables iterated by KTX's own mod-side dispatch
  (`commands.c`; the KTX command extractor's own docstring: "PATTERN 4 --
  struct-literal command tables iterated via dispatch"; KTX's
  `Cmd_AddCommand` call sites are commented out -- `teamplay.c`). The
  `mvdsv` `cmdlist` enumerates ONLY engine-side `Cmd_AddCommand`
  registrations. It therefore CANNOT observe the KTX mod-command surface at
  all: "absent from `cmdlist`" is the trivial structural default for ~100%
  of KTX commands and carries ZERO liveness information. (Contrast
  `ktx / cvar`, which IS valid: KTX cvars DO register into mvdsv's cvar
  system via `Cvar_Register`, so `cvarlist` enumerates them and that leg
  correctly yields 0 suspects.)

  the most-used commands in competitive QuakeWorld: `1on1`, `2on2`, `4on4`,
  `ready`, `break`, `captain`, `pickup`, `agree`, `yes`, `no`, `+scores`.
  These are unmistakably functional. The single `cmdlist`-intersection is a
  coincidental engine-command name collision, not a liveness signal.
- **Disposition (Executor correction 2026-05-17 -- see the dated note
  below).** This leg is EXCLUDED from the C3 suspect pool. It does NOT route
  to the D6 dead-stamp and Phase 3 MUST NOT dead-stamp any KTX command from

  KTX-mod-side oracle (or the parked libclang call-graph over the `cmds[]`
  dispatch) -- it is NOT a Phase-0 deliverable and NOT this arc's scope.
  This is distinct from F-C3b: F-C3b parks *classifying genuine suspects*;
  here the instrument produces *no valid suspects to classify*. Tracked:
  review-findings **F-C3c**.
- The raw 357-name difference remains reproducible from the committed script
