Hoonymode

Description slot

Hoonymode is a team-survival mode where players have a single life per round and the first team to eliminate the opposing team wins. Created by community member "hoony" as a higher-stakes variant of TDM. Built on the standard Game Content baseline with explicit deviations listed below.

Gameplay strategy slot

Because players have one life per round, positioning and timing trump aggressive engagements. Key tactics involve map control, item denial, and audio cue discipline. The single-life rule changes weapon priorities -- LG discharge goes from rare to never-use, and rocket jumping drops sharply as health management becomes paramount.

Deviations from Game Content baseline -- bones

  • Respawn: NONE within a round (single life; baseline = 5s respawn timer)
  • Spawn protection: 3s (baseline = 2s)
  • Quad damage: DISABLED (baseline = enabled, 30s respawn)
  • RA respawn: 25s (baseline = 30s)
  • Health regen: NONE outside MH pickup (baseline = none)

Mockup values for illustration -- actual deviations vary by KTX version.

History / origin slot

First introduced in KTX v1.45 by hoony as a response to community demand for higher-stakes team play. Adopted into competitive rotation at QHLAN 2018; became a regular sideshow at major events. Source: KTX commit history + QHLAN 2018 tournament page.

Notable matches -- bones

  • QHLAN 2018 Final -- TeamA vs TeamB (epic comeback from 0-3 down)
  • EQL S25 sideshow -- ClanX vs ClanY (5-round upset)

Wiki narrative -> hub by game ID. No per-match wiki page-type (Pass 3 schema enforcement + Pass 4 amendments).

Track C disciplines visible in the Hoonymode mockup

  1. Section-as-atom: Description / Strategy / History / Deviations / Notable matches each occupy one H3 with one focused topic. Curator can lift any section as a concept-note input atom.
  2. Self-contained sections: each section anchors back to Hoonymode (the parent concept) or Game Content baseline (the cross-link anchor) so readers entering at any section get local context.
  3. L1/L3 cross-refs: Game Content baseline / map control / item denial / LG discharge / rocket jumping all link to canonical entity pages.
  4. Citation discipline: KTX commit history, QHLAN tournament page, hub game IDs provide trace-back for every claim.

Race-vs-Hoonymode generalization test

Race is structurally different from Hoonymode (solo, time-trial, no opponents). Does the mode page-type generalize?

  • Sub-type field: "Race" toggles conditional infobox fields (Best times / Max time / Single-player flag instead of Win-condition).
  • Deviations-from-baseline: absorbs the structural diffs (no combat / no items / single player / no respawn timer in the conventional sense).
  • Notable runs (instead of notable matches): still external-link to hub by game ID.
  • Slots: description / strategy / history all still apply.

Conclusion: Hoonymode shape generalizes to Race via sub-type-driven conditional bones. The mode page-type works.
