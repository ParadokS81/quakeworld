# ezQuake Extractor -- Out of Scope

What ezQuake's libclang-based extractor does NOT capture, organized by the 4-bucket framework. Refresh whenever a re-extraction or runtime validation diff surfaces new gaps.

**Last reviewed:** 2026-04-28 (post-cross-extractor-arc, post-Mode-B-validation).
**Extraction total:** 4042 entities at head (post-arc canonical state).

---

## Bucket 1 -- Out of scope by design (source roots not visited)

ezQuake has no plugin system. This bucket is empty.

---

## Bucket 2 -- Dynamic registration via Cvar_Create (~4 cvars)

Cvars created at runtime when an `exec` references an unknown name. `Cvar_Create(name, value, flags)` is called from user-facing teamsay subsystem, not from static cvar_t declarations. Static extraction can never see these.

**Confirmed absent:**
- `nick` (user teamsay macro)
- `tpname` (user teamsay macro)
- `tp_version` (user teamsay macro)
- `loc_name_separator` (user teamsay macro)

**Fixable?** No. Fundamental static-analysis limit. These showed up in the runtime-only diff (Pass 1 validation) and were explicitly categorized as Bucket 2, not as extraction gaps.

**Trigger to revisit:** a user config references a teamsay macro not in the list above and slipgate's converter flags it as unknown. Add it to the documented set; there is no extraction fix.

---

## Bucket 3 -- Runtime-synthesized names (~5 HUD command aliases)

Names auto-generated by `HUD_Register()` at runtime, not visible as literal strings in source.

**Confirmed absent (command aliases):**
- `+hud_<name>` / `-hud_<name>` pairs (one per HUD element, ~46 pairs)
- Plain `<name>` HUD-edit commands (~83 names)

**Note:** the underlying HUD elements ARE in the DB under `type='hud_element'`. The associated cvars (e.g. `hud_netgraph_show`, `hud_netgraph_pos_x`) ARE captured via `_synthesize_hud_cvars()` in `extractor_lib/handler_cvars.py`. Only the runtime `+/-` command-alias bindings are absent.

**Fixable?** Partial. Could synthesize `+/-` aliases at extraction time by iterating extracted hud_elements and emitting mirror command rows. Deferred until a consumer use case justifies the synthesis logic.

**Trigger to revisit:** slipgate's bind parser encounters `+hud_netgraph` or similar in a config file and has no DB row to resolve against.
