## Summary

4on4 is QuakeWorld's flagship competitive team format: two teams of four players fight to out-frag each other over a 20-minute match. Its defining trait is that picked-up weapons do not stay on the ground (`deathmatch 1`), which turns the map's weapons, armor and powerups into contested resources -- so 4on4 is as much about controlling the map as about aim. It is the mode the organized QuakeWorld scene is built around, played on a small set of classic maps and run through long-standing leagues.

## How it plays

Two teams, four players each, friendly fire on (`teamplay 2`). You win by holding the higher frag count when the 20-minute clock runs out; a drawn match goes to a single 5-minute time-based overtime period. Each team needs at least three ready players before the match will start (`k_membercount 3`).

What makes 4on4 its own game rather than "a duel with more people" is the deathmatch flag. From three players per team upward, KTX runs `deathmatch 1`: a weapon you pick up does not respawn where it lay, so the rocket launcher, lightning gun, and the armor and health on the map are finite, timed resources that one team can deny the other. (Smaller formats -- 1on1, 2on2 -- run `deathmatch 3`, where weapons stay put, because in a duel a weapon should always be available.) This is why 4on4 revolves around map control, item timing, and coordinated team positioning: the team that owns the red armor and the quad spawn usually owns the match.

Powerups are live (`k_pow 1`) -- Quad Damage, Pentagram, and Ring of Shadows spawn on their map timers -- but they are not dropped when their carrier dies. A quad is a window the holding team presses while it lasts, not an item that changes hands on a kill (unlike FFA, which drops quad and ring on death).

## Starting a game

On a KTX server, type `/4on4` in the console. Any player can do it (or an admin spectator), but only before a match has started -- 4on4 sets a match up, it does not interrupt one. The server applies the 4on4 preset and is then ready for teams to ready up.

You can append an optional match tag -- `4on4 EQL` -- which labels the game for QTV event tooling, so spectators and the QTV layer can see the league or event a match belongs to.

The server has to allow the mode: if `k_allowed_free_modes` does not include the 4on4 bit, the command is refused. It is also blocked on hoonymode-only maps and while the auto-XonX feature is active.

## Maps

4on4 is played on a small, stable set of maps rather than the full id1 rotation. The classics are `dm3` -- the definitive 4on4 map -- along with `dm2` and `e1m2`. Beyond the id1 maps the competitive rotation has long included community maps: the `cmt` series (`cmt1b`, `cmt3`, `cmt4`, `cmt5pro`), the `ctl` set (`ctl5`, `ctl6`, `ctl8`), and standalones such as `schloss`, `phantombase`, `aztek`, `obsidian`, `rock`, `steam`, `stroggopolis`, `anwalk2`, and `e2m2tdm`. These are scene conventions, not anything KTX enforces: any map will load, but organized play sticks to the curated set (gathered on the community's `maphub_v2` server hub).

## History

4on4 predates KTX. It was the staple team format on KTPro servers before KTX became the standard QuakeWorld server mod, and KTX carried it forward as one of its built-in usermodes. It is the format the competitive scene has organized itself around for decades, through leagues such as NQR (Nations Quake Rumble) and EQL (European Quake League) and a long line of well-known clans.

## Hosting & settings

On a standard KTX or nquake server, 4on4 is available out of the box: `k_allowed_free_modes` defaults to `4095` (every standard mode), and 4on4 rides on the `UM_4ON4` bit (value `8`, shared with ca and wipeout). You only set the bitmask explicitly to *restrict* a server to a subset of modes; any mask that includes 8 keeps 4on4 available:

```
# server.cfg -- the standard default; the 8 bit covers 4on4 / ca / wipeout
set k_allowed_free_modes 4095
```

`k_allowed_free_modes` is read once at map start, so a change needs a map restart to take effect.

The 4on4 ruleset itself is fixed in KTX and applied by the `/4on4` command -- an admin does not normally tune it per match. The settings that define the mode:

- **`deathmatch 1`** -- weapons do not stay on pickup. The single most defining setting, and the reason 4on4 plays the way it does (see How it plays).
- **`maxclients 8` / `teamplay 2`** -- eight players, two teams, friendly fire on.
- **`timelimit 20`** with **`k_overtime 1` / `k_exttime 5`** -- 20-minute matches, a 5-minute timed overtime on a draw.
- **`k_pow 1`** -- powerups spawn on the map (`dq` / `dr` are left off, so powerups are not dropped on death).
- **`k_membercount 3`** -- each team needs three ready players before the match can begin.

After applying the preset, 4on4 also loads any `configs/usermodes/4on4/*.cfg` files present on the server, so an operator can layer their own overrides. Note that the "approved rules" leagues publish -- which sometimes add settings such as `fallbunny` -- are league and server conventions layered on top; they are not part of the KTX `/4on4` preset.

## See also

- `ca`, `wipeout` -- arena modes that share 4on4's activation bit (`UM_4ON4`) on the server, though they play very differently.
